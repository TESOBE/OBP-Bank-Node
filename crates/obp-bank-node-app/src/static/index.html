OBP Bank Node — Open Corridor

accounts · setup

1 Send

POST an OPEN_CORRIDOR A1.1 request to a node's south-side API.


      

    


    

      
2 Promise

      
Each node's outbox: INITIATED → SUBMITTED → PROMISE_WRITTEN → REPORTED.
        The on-chain promise is a salted SHA-256 commitment — hash only; cleartext and salt stay with the banks.

      

    


    

      
3 Credit

      
Beneficiary-side evidence, delivered at promise time: the commit–reveal triplet, whether
        SHA-256(salt ‖ preimage) matched the on-chain commitment, the CBS delivery result,
        and the settlement stamp once an obp_settlement_advice covers it.

      

    


    

      
4 Position

      
This bank's unsettled outbound exposure per corridor
        (SUBMITTED/PROMISE_WRITTEN/REPORTED, not yet covered by a settlement).
        A node only knows its own outbound legs — the authoritative bilateral net is computed by
        OBP-API at settle time (see the corridor view in step 5).

      

    


    

      
5 Settle

      
Ask a node to trigger bilateral settlement: it calls OBP-API's settlement resource over
        Interface B; the net moves later on the rail (SETTLING → SUBMITTED → FINAL).

      

        

          
          
          
        

        
        

      

      

      

    


  


  

    
Note: This application does not hold, move, or decide anything about money.
      It only reads state from the Bank Nodes and triggers their documented endpoints —
      validation, promises, netting and settlement happen in the Bank Nodes and OBP-API.
      Everything shown here can be re-read from a node API; if this application were
      switched off, payments would be unaffected.
